фнализатор - метод который гарантировано очистит память которые сборщик не успел 
IDisposable - метод который дает пользователю контроль над временем очистки 

кт 43
1 полный паттерн Dispose(bool disposing): разделяет освобождение управляемых и неуправляемых ресурсов. При явном вызове Dispose() (disposing = true) освобождаются и управляемые объекты  и нативная память . При вызове из финализатора  управляемые поля не затрагиваются, так как к моменту финализации они уже могут быть собраны сборщиком мусора, и очищается только неуправляемый дескриптор.
2 Роль GC.SuppressFinalize(this): при штатном выходе из using или await using объект удаляется из очереди финализации. Благодаря этому он не задерживается на дополнительный цикл сборки мусора и освобождается быстрее.
3 Защита и идемпотентность: флаг disposed гарантирует, что повторный вызов Dispose() не приведёт к двойному освобождению нативной памяти (ошибке повреждения кучи), а попытка вызова рабочих методов  после освобождения выбрасывает ObjectDisposedException.
4 IAsyncDisposable и await using : необходимы для классов, работающих с асинхронным вводом-выводом  Конструкция await using вызывает DisposeAsync(), позволяя асинхронно сбросить буферы на диск  и закрыть поток без блокировки потока выполнения.
